Rounds 1–5 were not merely technical rule rounds. They contained substantial future-product planning.

A later audit error occurred because a legacy product label—Reading Room（阅读室）—survived in the workshop order without being independently revalidated.

# 1. Future platform direction actually established / 真正确立的未来平台方向

## P1 — Broader platform, not a permanent East-only specialist site
The long-term platform was reframed beyond a narrow ancient-text or East-only destination.

Accepted product direction includes:

- culture / knowledge / context / real-world experience;
- community interaction;
- discovery/recommendation;
- travel/local knowledge and future domains;
- stronger structure/provenance than a generic social feed;
- Eastern/Chinese culture as the initial wedge, not permanent total scope.

This is directly reflected in the Round 3 platform-scope correction.

## P2 — Multi-lane content/knowledge system
The platform is not one generic Article/blog database.

Planned product lanes include:

- Canonical / source-backed classical-text reading and research;
- Editorial / teaching / interpretation content;
- Contributor publications;
- Community / user publications;
- Discussion linked to works/passages/topics;
- Issue（议题） editorial curation over the broader system.

## P3 — A real reading experience exists, but not a confirmed “Reading Room” product
Post-reset planning clearly includes **reading surfaces and reading-related capabilities**:

- canonical classical-text reading/research surface;
- normal editorial/publication reading surfaces;
- related reading;
- Save / Bookmark（收藏 / 书签）;
- Follow（关注）;
- Reading History（阅读历史） as a possible behavioral/input primitive;
- private notes / saved passages as future reader capabilities;
- Topic / Place / Text / Work relations that support reading/discovery.

What is **not** supported by the post-reset sources is a decision that these must be bundled into a distinct product/container called Reading Room（阅读室）.

## P4 — Community is a core product system
Community was explicitly discussed as a future platform-level primitive.

Current early planning direction included:

- one underlying Community/content graph rather than isolated forums;
- scoped views by Domain / Topic / Place / Following;
- a cross-domain Home / For You（首页 / 为你推荐） discovery surface;
- user-generated publications, discussion/replies and reader reflections;
- canonical/source surfaces remain clean while discussion lives in companion Community objects.

## P5 — Discovery is not category-first
The user should be able to open the platform without already knowing what category to choose.

The accepted early product direction includes:

- mixed cross-domain Home / For You;
- scoped views such as Topic / Place / Following;
- recommendation/exploration to avoid information cocoons;
- fair discovery for low-traffic high-quality works.

## P6 — Durable user publishing
Ordinary users can create durable, searchable, linkable publications.

These are not disposable feed posts. They can retain:

- stable identity/permalink;
- search/discovery;
- save/follow/recommendation relationships;
- Topic / Place / source links;
- archival/cultural value;
- future editorial curation.

## P7 — Profile/identity has a product role
The early plan explicitly distinguishes:

> Profile explains identity; Content is judged as work.

Profile/detail surfaces may carry richer identity/qualification context; feed/content cards should not over-amplify prestige.

## P8 — Membership exists as a future product/business subject, but its benefit bundle was not defined
Membership/VIP was discussed repeatedly in Rounds 1–5, mainly to define what payment **cannot** buy and to defer the actual bundle.

Confirmed early direction:

- Membership may provide legitimate product benefits;
- it may reduce some anti-Sybil/economic-friction constraints for selected capabilities;
- it cannot manufacture authority, Contributor Qualification, Work Recognition, Reviewer Trust, Governance Authority or organic reach;
- exact Membership benefit package remains deferred to the Membership round;
- benchmark ideas such as saved/archive capabilities, quality-of-life tools, customization, creator tools or member surfaces were only candidate references, not accepted benefits.

**No accepted Round 1–5 source defines Reading Room as a required Membership product.**

# 2. Reading-related concepts actually present / 实际存在的“阅读”概念

The user's memory that the plan already contained “a place/experience for users to read” is consistent with the sources.

The post-reset product plan contains at least these reading concepts:

1. Canonical Classical Text reading/research surface（古籍原典阅读 / 研究界面）
2. Editorial/teaching publication reading（编辑 / 教学内容阅读）
3. Community/user publication reading（社区 / 用户作品阅读）
4. Related Reading（相关阅读）
5. Save / Bookmark（收藏 / 书签）
6. Follow（关注）
7. Reading History（阅读历史）
8. future Private Notes（私人笔记）
9. future Saved Passages（保存段落）
10. Topic / Place / Text / Work navigation（主题 / 地点 / 文本 / 作品导航）
11. Home / For You（首页 / 为你推荐） as a mixed discovery entry
12. Following / scoped views（关注 / 范围视图）

These are **capabilities/surfaces**, not proof of one unified personal “Reading Room” container.

# 3. Community concepts actually present / 实际存在的社区规划

Post-reset planning explicitly established:

- one shared Community substrate;
- multiple Topic / Domain / Place projections;
- global mixed discovery;
- user publishing;
- replies/discussions;
- reader reflections;
- companion discussion attached to canonical works/passages without polluting canonical records;
- future moderation/governance;
- profile/identity separation from work quality;
- Follow / Save / discovery relations across the platform.

Therefore Community is not an old-plan residue in the same way Reading Room is. It was re-discussed and revalidated.

# 4. What was NOT established in Rounds 1–5 / 第一至第五轮没有确立什么

No accepted post-reset Round 1–5 source establishes:

- a required distinct Reading Room product;
- a private member-only reading center;
- a VIP Library;
- article/Archive paywalls;
- a Reader / Patron tier model;
- a member-only Reader Notes system;
- a Patron voting product;
- a fixed personal reading dashboard;
- a rule that Save / Notes / Reading History must live in one dedicated page.

These belonged to old planning or remained unresolved.

# 5. Why the confusion happened / 为什么会混进来

The original workshop order imported the old label:

`Membership / Reading Room`

as a future subject.

But the post-reset “already locked” product principles did **not** include Reading Room as an approved product.

Later rounds treated the phrase as deferred shorthand, so the inherited noun survived without passing a product-existence decision.

That was a provenance failure, not evidence of a user-approved Reading Room.
