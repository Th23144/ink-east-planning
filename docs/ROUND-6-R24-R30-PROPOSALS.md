# Round 6 R24-R30 proposals

Status: PROPOSED / NOT YET ACCEPTED. Round 6 remains reopened and not sealed.

- R6-R24: when a platform worker/service acts for another principal, preserve both the requesting principal and executor in consequential provenance.
- R6-R25: permissions, scopes and approvals bind to stable internal object identity rather than only mutable/reusable visible identifiers.
- R6-R26: derived grants preserve enough source lineage for proportionate review when their source later becomes invalid, while normal offboarding does not force universal cascading revocation.
- R6-R27: consequential authority/control state changes are committed against a coherent current state so concurrent changes cannot rely on incompatible stale state. Technical mechanism is deferred.
- R6-R28: bounded approvals/invites/transfers have lifecycle semantics that prevent unintended repeated use while allowing safe retry.
- R6-R29: successor/guardian/executor/legal-representative status gives no automatic private-data or login access; any lawful exception is separate, scoped, auditable and privacy-minimized.
- R6-R30: authorization-policy and sensitive control-rule changes are themselves scoped, permissioned and auditable; engineering access alone does not imply authority to redefine business/security permissions.

If accepted, these are incorporated into one clean R1-R30 consolidation before the next parity and frozen-matrix pass.
