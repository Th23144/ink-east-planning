## 1. Why evidence rules are needed（为什么需要证据规则）

Early Co-builder Relationship（早期共建者关系） is historical and cannot be bought later.

Therefore the platform eventually needs a reliable way to answer:

> **What actually happened, when did it happen, and what kind of early co-building history does it support?（实际发生了什么、发生在什么时候、它支持哪一种早期共建历史？）**

This must remain lightweight enough not to turn community belonging into bureaucracy（不能把社区归属做成官僚审核）.

---

## 2. Typed evidence, not one universal threshold（按类型留证，而不是统一门槛）

Each co-building history may use evidence appropriate to that history.

### A — Early Presence（早期在场）
Possible evidence:
- account creation / first meaningful activity time（账户创建 / 首次真实活动时间）;
- sustained early activity（持续早期活动）.

### B — Financial Support（资金支持）
Possible evidence:
- completed supporter/payment record（完成的支持 / 付款记录）.

Amount/frequency should not convert into authority or rank（金额 / 频率不转化为权威或等级）.

### C — Quality Publishing / Knowledge Participation（优质发布 / 知识参与）
Possible evidence:
- publication history（发布历史）;
- durable content/community contribution record（持续内容 / 社区参与记录）;
- later applicable quality/recognition evidence where independently relevant（未来独立适用的质量 / 认可证据）.

This does not create Contributor Qualification（贡献者资格） automatically.

### D — Network Growth（网络增长）
Possible evidence:
- legitimate referral attribution（真实推荐归因）;
- durable retained users / community formation（真实留存用户 / 社区形成）;
- non-spam relationship creation（非垃圾式关系建立）.

Raw invite count alone is insufficient（单纯邀请数量不足）.

### E — Product Co-building（产品共建）
Possible evidence:
- beta participation（测试参与）;
- accepted/actionable feedback（被采纳 / 可执行反馈）;
- reproducible bug reports（可复现问题报告）;
- product research history（产品研究参与历史）.

### F — Cultural Recovery / Project Participation（文化寻回 / 项目参与）
Possible evidence:
- existing Recovery Role / Attribution（寻回角色 / 归因）;
- project records（项目记录）;
- documentation / research / digitization participation（记录 / 研究 / 数字化参与）.

Existing Recovery semantics remain controlling（现有寻回语义继续控制）.

---

## 3. Self-claim is input, not truth（自述是输入，不是真相）

A user may be allowed to say:

> “I helped with X during the early stage（我在早期帮助过某件事）.”

But self-claim alone should not silently become confirmed historical record（自述不能自动变成已确认历史记录）.

Possible model:
- user claim（用户自述）;
- platform/project evidence（平台 / 项目证据）;
- corroboration where needed（必要时佐证）;
- confirmed typed history（确认的类型化历史）.

Exact UX（用户体验） remains later.

---

## 4. Preserve provenance and context（保留来源与上下文）

Where practical, a confirmed historical record should preserve:
- what happened（发生了什么）;
- time / stage（时间 / 阶段）;
- related object/project（相关对象 / 项目）;
- evidence source（证据来源）;
- later correction/dispute history if needed（必要时的后续纠正 / 争议历史）.

This allows history to be explainable rather than a mysterious badge（避免变成来历不明的徽章）.

---

## 5. No “founder court（创始者法庭）” by default

The system should not require heavy manual adjudication for every early activity.

Prefer:
- automatic durable records where the platform already has reliable logs（已有可靠记录则自动保存）;
- lightweight confirmation where context is clear（上下文清楚时轻量确认）;
- manual review only for ambiguous/high-impact historical claims（只有模糊 / 高影响历史主张才人工复核）.

---

## 6. Current decision questions（当前决策题）

1. Should Early Co-builder（早期共建者） history be evidence-backed and typed, rather than granted by a vague global label?
2. Should different history types use different evidence standards instead of one universal threshold?
3. Should user self-claims be allowed as input but never auto-confirmed as historical truth?
4. Should confirmed history preserve time/context/evidence provenance so it remains explainable?
5. Should the platform prefer automatic/lightweight recording and reserve manual review for ambiguous or consequential cases?
