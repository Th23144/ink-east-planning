# Round 12 — External Premium Pattern Benchmark V1
# 第十二轮——外部大型平台 Premium 模式基准研究 V1

> **Status:** RESEARCH / NON-CONTROLLING（研究 / 非控制性）
> **Date checked:** 2026-10-01
> **Purpose:** determine what is useful to study from current large-platform subscription patterns without copying any platform mechanically.
> **Important:** external platform behavior is evidence/reference only; it does not override Project 3 Current Truth.

---

# 1. Research question / 研究问题

Project 3 has revalidated Open Core, contextual payment-as-economic-friction, and the separation of payment from authority, Recognition, governance and organic recommendation advantage.

The benchmark asks:

> Do major social/community platforms commonly require paid Membership for the core product loop, and which premium patterns are structurally relevant to Project 3?

---

# 2. Current platform patterns / 当前平台模式

## X Premium

Official current X documentation shows Premium includes longer posts, longer video uploads, edit post, bookmark folders, Community creation, reduced/no ads at higher tiers, Articles for higher tiers, reply prioritization, and other creator/AI/media tools.

Sources:
- https://help.x.com/en/using-x/x-premium
- https://help.x.com/en/using-x/how-to-post

### Project 3 relevance

**Partially relevant:**
- higher publishing/media capacity is a useful reference pattern.

**Poor fit / reject as a model:**
- reply prioritization conflicts with Project 3's separation of payment from organic Recommendation/distribution;
- making long-form creation permanently Premium-only is more aggressive than Project 3's Rounds 1–5 rule, where legitimate non-paying accounts can eventually gain broader publishing capability.

---

## Reddit Premium

Current Reddit Premium includes ad-free browsing, new-comment highlighting, higher post-body and video limits, account-level performance analytics, custom icons/avatar benefits and other Premium utilities.

Source:
- https://support.reddithelp.com/hc/en-us/articles/360043034412-What-is-a-Reddit-Premium-subscription

### Project 3 relevance

This is structurally closer than X for **capacity enhancement**:

- ordinary users can still create substantial content;
- paid users receive higher limits rather than exclusive ownership of the entire capability.

However, Project 3 still requires its own anti-abuse justification; Reddit's commercial choice is not itself proof that a limit should be paid.

---

## Telegram Premium

Telegram states that Premium is optional and includes doubled limits, larger per-file upload capacity, faster downloads, voice-to-text, advanced chat management, cosmetic/expressive features and other enhancements.

Source:
- https://telegram.org/faq_premium/

### Project 3 relevance

Useful reference for:

> **core communication remains available; Premium increases capacity/convenience around an already-working product.**

This aligns better with Open Core than a hard capability paywall.

---

## Discord Nitro

Current Discord documentation describes Nitro as premium account perks including HD streaming, larger file uploads, cross-server/custom emoji use, profile/avatar customization, themes and other enhancements.

Source:
- https://support.discord.com/hc/en-us/articles/34679678303255-Discord-Nitro-September-2025-New-Look-Offer

### Project 3 relevance

Useful reference for:

- real bandwidth/storage/media-capacity enhancement;
- optional personalization;
- keeping the central communication/community loop usable without subscription.

It does not justify inventing equivalent perks before Project 3 has those real needs.

---

## Snapchat+

Current Snapchat support describes Snapchat+ as access to exclusive, experimental, pre-release, customization/AI and other optional features, with ad-reduction in some plans.

Source:
- https://help.snapchat.com/hc/en-us/articles/7121577610900-What-is-Snapchat

### Project 3 relevance

Useful mainly as an example of optional experimentation/personalization.

Not a strong reason for Project 3 to create member-only features merely to imitate a consumer-social subscription.

---

## Meta Verified

Meta's published material has framed Meta Verified around identity authentication/verified badge, impersonation protection, account support and other creator/business benefits.

Sources:
- https://about.fb.com/news/2023/06/expanding-meta-verified-to-india/
- https://about.fb.com/news/2023/09/meta-verified-for-businesses/

### Project 3 relevance

The account support/security idea may be studied independently if Project 3 later has a real support-cost problem.

The verification model must **not** be copied into Project 3's epistemic/qualification architecture because Project 3 already separates factual verification, Contributor Qualification, Recognition and governance, and payment cannot manufacture those forms of standing.

# 3. Cross-platform pattern / 跨平台共同规律

The major pattern is not:

> “Pay or the social platform does not work.”

It is closer to:

> **The core loop is broadly usable without subscription; Premium monetizes capacity, convenience, personalization, ads, costly infrastructure, support/security, experimentation, or creator tooling.**

X is comparatively aggressive in placing some creation/distribution capabilities behind paid tiers.

Even X still leaves the basic posting/reading social loop available without Premium.

---

# 4. Product-architecture verdict for Project 3 / 对项目三的产品架构判断

## Do not copy X wholesale

Project 3 should **not** use X Premium as its default Membership template.

Specifically reject:

- paid organic-distribution advantage;
- payment-based authority;
- making ordinary durable publishing permanently paid-only.

## Stronger reference pattern

For Project 3's already-confirmed anti-abuse rule, the closer structural references are:

- **Reddit** — free core creation + higher paid capacity;
- **Telegram** — open core + doubled/higher limits;
- **Discord** — open community loop + paid resource/convenience enhancement.

But Project 3 should go one step further:

> a paid capacity change should exist only where the specific restriction has a real anti-abuse or resource-cost rationale.

---

# 5. Implication for Round 12 / 对第十二轮的含义

External benchmarking does **not** show that Project 3 needs to invent a large bundle of Premium-only features.

It supports a safer sequence:

Open core
→ identify real abuse/cost/capacity constraints
→ decide whether payment legitimately changes that constraint
→ do not let payment become trust/authority/distribution
→ only then consider optional commercial packaging.

Therefore the next Round 12 decision should not be “which platform do we copy?”

It should be:

> **Does Project 3 need Membership as a recurring consumer product beyond the already-confirmed economic-friction role of payment?**

That remains a genuine product decision.
