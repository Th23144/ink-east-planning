Anatomy — one note, eight hooks

解 剖

Read the demo from the inside out. Each numbered chip inside the note is a DOM hook the WordPress comment template must produce. Captions on the left and right name the hook and explain what it carries. The dashed lines are not decorative.

Author display name 1
display_name from wp_users; pen names live in user_meta('ie_pen_name') and override when present.
Relative timestamp 3
Format: "two days ago · 兩 日 前" for ≤14 days, then absolute "on May 12". Never SNS-style "5d".
Note body typography 5
Serif body, line-height 1.72, em for emphasis, blockquote for inline quotes. Paragraphs allowed. No HTML chrome.
Reply entry 7
Plain italic text link, not a button. Hidden when the note itself is a reply (max_depth = 1).

States — eight specimens

狀 態

Each block below is a complete render of the component in one state. The mono-cap label row above each block tells the engineer which tier triggers the state and which fields differ from the default. Read top to bottom; the first state is what an unsigned guest meets.

Group A · Empty / first-time states No notes have been left on the article yet. Two variants: guest (inert, with a sign-in invitation) and a logged-in member (composer ready, placeholder copy guides the first note).
State #1 Empty · guest tier = guest default render

This state shows: a reader who has not signed in, on an article with no notes yet. The composer is replaced by a quiet sign-in box. No "you must register" copy — it is an invitation, not a gate.

No notes yet on this essay. Reader Notes are open to Reader and Patron members.
— You're reading as guest —
Sign in to leave a note

Or become a member — both Reader and Patron tiers carry the writing right.

State #2 Empty · logged-in member tier = Reader / Patron

This state shows: a signed-in Reader or Patron, on an article with no notes yet. The sign-in box is replaced by an active composer. The placeholder copy is editorial, not breezy — it nudges the reader toward a real response, not a like.

What Bao writes about the chair pulled out before the guest arrives arrived for me at the wrong time, then again at the right time. The first reading I noticed only the gesture — the small, slightly anxious courtesy of preparing. I was tired and did not look further. A week later, on a quieter evening, I came back to the paragraph and saw what was actually under it: not a courtesy, but a refusal of waiting.

The hour before the hour is not preparation; it is a small, secret rehearsal of the thing one is afraid will not arrive.

There is a Tao Yuanming poem I have been reading alongside it, in which the poet returns home not to rest but to refuse the office. Different vocabulary, same posture. Quiet is sometimes a very loud decision. Anyway — thank you for the issue. I will be slower this week because of it.

Red lines — what this is not

紅 線
— Read this paragraph before adding any new affordance —

This is not Reddit. It is not a tieba 貼吧 board, not Disqus, not wpDiscuz, not the comment well at the bottom of a news site. There are no upvotes here, no downvotes, no like counts, no heart taps, no reaction emoji. We do not display follower numbers, we do not allow a second nested reply, we do not collapse threads under a "Show 14 more" fold. A note is read in full or it is not posted. If you want to disagree with a note, you reply to it once and that reply stands or it does not — there is no thread under your reply, and no "controversial" sort to surface the loudest disagreement. Tiers are marked with a single Chinese character, not a coloured chip; timestamps are written in words, not the abbreviated "5d" SNS shorthand. The submit button reads Leave a note, never Post or Comment. The component is meant to feel like a margin written in pencil — an annotation kept alongside the essay — not a comments section.

陸

WordPress contract — field map & endpoints

後 端 契 約

The component is rendered server-side by a custom comment template that walks the article's wp_comments rows. v1 is pure PHP — no AJAX, no client-side rehydration. No plugin replaces the renderer. wpDiscuz, in particular, is not installed: it overrides the typography and ships its own chrome, both of which break the contract above.

Comment table
wp_comments · native WP table, no replacement One row per note. No custom post type — comments are first-class WP entities and the moderation UI in /wp-admin already exists.
Comment template
themes/ink-east/comments.php + walker-reader-notes.php Custom Walker_Comment subclass that emits the exact DOM in this spec — the .rn-note shape, the tier mark, the citation ref. Do not install wpDiscuz (BRIEF §六, handoff §3).
Editor's Choice
comment_meta key = editors_choice · type = bool · default = 0 Set from the comment row in /wp-admin → Comments via a "Mark as Editor's Choice" row action. Renders state #5 above. No public toggle.
Hidden by editor
comment_meta key = hidden_by_editor · type = bool · default = 0 When 1, the walker substitutes the body for the placeholder copy in state #6 and anonymises author + skips the actions row. The row stays in the list — see state #6 spec.
Author tier
user_meta key = ie_tier · enum = guest · reader · patron Read at render time from the note's user_id. Drives the tier mark (讀 / 贊) and the .tier.patron seal-red treatment. Editors are not rendered as a tier in the public component.
Reply parent
comment_parent · native WP column · max_depth enforced server-side The walker rejects any insert where the parent itself has a non-null comment_parent — i.e. max_depth = 1. The CSS already removes the reply affordance on rendered replies (state #7), but the server enforces independently of the markup.
Sort · Recent
ORDER BY comment_date DESC Default. Drives the Recent · 新 pill. No paging in v1 — show all approved notes for the post.
Sort · Editor's Choice
WHERE meta(editors_choice) = 1 ORDER BY comment_date DESC Drives the Editor's Choice · 編 選 pill. When the result set is empty, render the empty-state copy from state #8: "No editor-chosen notes yet on this article."
REST (read-only, future)
GET /wp-json/wp/v2/comments?post={id}&per_page=10&order=desc Hint for future Community page (#5b roadmap) and the Reading Room "Your Reader Notes" block. v1 does not call this — server-rendered comments are enough. Custom endpoint /wp-json/ie/v1/reader-notes can wrap with editors_choice meta when needed.
Permission gate
current_user_can('publish_comments') + ie_tier ∈ {reader, patron} Both must pass for the composer to render. Guests get the sign-in box (state #1). Editors do not write notes through this surface — they speak in essays.
Submit button copy
"Leave a note" · or, for replies: "Send the note" Hard-coded in the template. Never "Post", "Comment", or "Reply" — that vocabulary is from a different product.
